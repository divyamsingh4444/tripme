TripME — user flow

From first visit to a reminded trip  ·  13 steps, 3 gates  ·  Release 0.1.1 · every step exists in the deployed product

step GATElocked until met optional shortcut / return ↩backward edge
1

Land — or open a sample

Landing page. A finished plan is shown before anything is asked.

2

Choose the travel path

Planner entry · solo, couple, group, family, pilgrimage, corporate — six different question sets.

3

Give the brief

Mood · budget · days · origin · date. No assumed defaults; validated client-side.

4

The pipeline runs

Agent stream · seven agents report live, one by one, with per-agent failure states.

5

Read the plan

Trip page · destination evidence, budget split, day-by-day, arbitration.

6

See what happens next

The four-step stepper states the whole sequence from the moment a plan exists.

7

Adjust — optional

Swap destination, transport, stay, any day. Every change re-prices the trip in code.

8

Approve each booking

Booking cards, all simulated and labelled.

GATE · A PRICE CHANGE REVOKES ITS APPROVAL
9

Sign in

Google, or the password-less test user.

GATE · ONLY TO CONFIRM OR SAVE
10

Confirm the trip

Locks the plan; undo any time.

GATE · NEEDS 8 COMPLETE + 9 SIGNED IN
11

Opt in to reminders

Off by default, per trip, off again in one click. Schedule rebuilt from the accepted choices.

12

Get reminded

The bell — departure, check-in, each day. Optional email snapshot to the signed-in address.

13

Return

My Trips — saved with status, no duplicates. Preferences shorten the next brief.

IF AN AGENT FAILS

It fails over across three models. If a stage still fails, the page names the agent and the reason — the rest of the plan survives.

OUT-OF-SCOPE ASK

A non-India destination is named at the form, and Discovery opens by explaining the substitution. Never silently swapped.
